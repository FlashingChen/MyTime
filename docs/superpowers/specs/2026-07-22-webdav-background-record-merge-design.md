# WebDAV 后台同步与逐记录合并设计

**状态：** 已获设计确认，等待规格审阅

## 目标与范围

将当前仅由用户手动触发、整快照最后写入优先的 WebDAV 同步升级为：

- 用户新增、编辑或删除记录、分类后，自动提交一次网络约束的 Android 后台同步任务。
- 连续本地变更合并为唯一任务；不执行固定周期轮询。
- 同步文档按记录和分类 ID 逐实体合并，而不是让整个快照相互覆盖。
- 同一实体在两端均变更时，本机版本优先。
- 删除以墓碑表示并保留 90 天，阻止旧端副本重新出现。
- 使用 ETag 条件请求防止盲写；服务器支持时辅助使用短生命周期 WebDAV 锁。

本次不实现字段级合并、冲突副本、跨账户同步、多远端目标或 iOS/Web 后台调度。

## 架构边界

领域模型 `TimeRecord` 和 `Category` 保持业务字段不变。新增独立同步元数据存储，不把同步时间、墓碑或 ETag 写入业务模型、Bloc 或 Widget。

新增或演进的同步边界：

- `SyncMetadataStore`：持久化每个记录/分类 ID 的本地修改时间、删除墓碑时间、已确认的远端 ETag 和锁能力缓存。
- `SyncMutationTracker`：Repository 成功写入后，更新相应实体元数据；删除时写入墓碑。它还通知后台调度器。
- `SyncScheduler`：平台抽象。Android 实现用唯一、网络约束的 WorkManager 任务；不支持后台调度的平台实现为安全 no-op，前台同步仍可用。该实现需要引入一个维护中的 Flutter WorkManager 插件，作为本功能唯一的新依赖。
- `SyncPort`：传输层返回远端文档及 ETag，并支持带前置条件的写入；可选暴露获取和释放 WebDAV 锁的能力。
- `WebDavSyncCoordinator`：在已有进程内串行化基础上，编排拉取、锁、逐实体合并、条件上传、冲突重试与确认状态持久化。

现有 `SyncDataGate` 继续作为本地批量写入与应用写入之间的互斥边界。同步层继续只依赖 Repository Port，不直接访问 Hive。

## 同步文档与迁移

远端 JSON 升级为版本 2。它包含记录、分类、每类实体的同步元数据和墓碑。每个非删除实体都有 `updatedAt`；墓碑包含实体类型、ID 和 `deletedAt`。文档仍包含整体 `updatedAt`，仅用于诊断和文档版本管理，不参与实体冲突判定。

客户端必须接受现有版本 1 文档：将其记录和分类视为未删除实体，并以文档 `updatedAt` 初始化其远端实体时间。首次成功同步以版本 2 覆盖远端文档。

每次成功同步先清理 `deletedAt` 早于当前时间 90 天的墓碑，再上传清理后的合并文档。清理只在成功的条件写入后确认，避免网络失败导致本地和远端观察到不同状态。

## 合并规则

记录、分类分别按 ID 执行同一算法：

1. 仅本地或仅远端存在且未被有效墓碑删除的实体，进入合并结果。
2. 一端是有效墓碑、另一端是实体时，墓碑获胜；因此离线设备中的旧副本不会复活。
3. 两端都是实体且内容相同，保留一个版本并使用较新的同步时间。
4. 两端都是实体且内容不同，本机版本获胜，不比较时间戳。
5. 两端都是墓碑，保留删除时间较晚的墓碑。

分类合并完成后，若一个保留记录引用的分类不存在或已被墓碑删除，将该记录的 `categoryId` 清空。结果仍需满足现有快照校验的至少一个分类约束；不得通过远端合并产生空分类库。

本地应用合并结果时，Repository 批量替换继续具备失败回滚语义。成功后才更新同步元数据与远端 ETag。

## WebDAV 并发协议

同步开始时执行 GET，读取文档和响应 ETag。不存在的文档视为首次同步。

若服务支持 `LOCK`，以短超时申请独占锁并在 `finally` 中用 `UNLOCK` 释放；服务返回不支持锁的状态时，记录该能力并继续，不将其视为同步失败。锁不是正确性的前提。

上传规则：

- 已存在文档：PUT 带 `If-Match: <GET 的 ETag>`。
- 不存在文档：PUT 带 `If-None-Match: *`。
- PUT 返回成功：使用响应 ETag；服务未返回时，再次 GET 读取确认 ETag。
- PUT 返回 `412 Precondition Failed`：重新 GET、重新合并、重新条件 PUT，最多重试三次。
- 超过重试次数时，不覆盖远端，也不确认本地同步元数据，任务按可重试网络冲突失败处理。

认证失败、配置无效或远端文档格式无效不自动循环重试；网络 I/O、超时和 `412` 耗尽可按后台调度器退避策略重试。所有失败在设置页显示可理解的最近同步状态。

## 后台执行与界面

记录或分类的成功新增、更新、删除均通知 `SyncScheduler`。调度器仅在 WebDAV 配置完整时创建 WorkManager 唯一任务，约束为已连接网络；新请求替换或合并尚未执行的相同任务，从而把连续编辑收敛为一次同步。

后台任务在独立 Dart isolate 中初始化 Hive、偏好与安全存储，并从已保存的 WebDAV 配置构建同步依赖；不得捕获或复用前台内存中的 Bloc、Repository、Coordinator 或密码。任务复用与“立即同步”相同的 Coordinator 和合并规则。用户仍可从设置页面点按立即同步；它在应用进程中执行并与后台任务串行化。

设置页文案改为说明“本地编辑后将在网络可用时自动同步”，并展示最近一次同步成功时间或可操作错误。原型、README、架构说明和 CHANGELOG 必须同步这一行为。

## 验证策略

- 单元测试版本 1 解码和版本 2 编解码、无效元数据及 90 天墓碑清理。
- 单元测试逐记录/分类合并：不同 ID 双向保留、同 ID 冲突本机优先、墓碑阻止复活、分类删除清理记录引用。
- 单元测试 ETag 的 `If-Match`、首次创建的 `If-None-Match`、412 重新拉取合并重试、三次耗尽、锁不支持降级和锁始终释放。
- 单元测试 Repository 变更成功后创建元数据和唯一后台任务，失败写入不调度。
- Android 集成或平台适配测试验证网络约束与唯一任务配置；平台无后台任务实现不影响手动同步。
- 运行 `flutter analyze`、`flutter test`，并在 Android 设备验证编辑后离开应用仍能在网络恢复时完成一次同步。
